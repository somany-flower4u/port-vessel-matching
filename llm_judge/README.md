# LLM 철자 판정기 사전 연구

`submission/model/llm/judge.py`의 설정(모델, 프롬프트, τ, κ, 부분집합 가드)을 정하려고 돌린 분석 스크립트입니다.
- `τ`: 판정할 순위 점수 차 구간
- `κ`: 2위로 바꾸는 데 필요한 로그 확률 차

판정기는 후보 영문명이 주어졌을 때 그 행의 한글 표기가 나올 로그 확률 `log p(한글 표기 | 영문명)`를 계산합니다.

| 파일 | 내용 |
|---|---|
| `prep.py` | 평가셋 A~D와 점수를 매길 (영문명, 한글 표기) 쌍 목록을 만듭니다. 각 평가셋은 아래 표에 있습니다. |
| `oof_neg.py` | 평가셋 E를 만듭니다. 실제 train 한글 행마다, 그 선박을 학습에서 뺀 폴드 인코더 기준 가장 헷갈리는 오답 후보를 찾습니다. |
| `sisters.py` | 실제 자매선 쌍을 찾습니다. 톤수·국적·길이가 같고 이름이 한 단어만 다른 카탈로그 선박입니다. |
| `judge.py` | 고정된 언어 모델로 쌍마다 로그 확률을 계산합니다. 프롬프트 형식은 `ko0`(제로샷), `ko10`(10-shot), `en10`입니다. |
| `analyze.py` | 평가셋별 정확도, κ별로 확신하며 틀리는 비율, 합성 검증셋의 τ×κ 격자(고친 행/틀리게 만든 행)를 출력합니다. |
| `domcurve.py` | 합성 검증셋에서 행 종류별 개입 곡선과 자매선 가드 효과를 봅니다. |
| `project.py` | 실제 쌍에서 얻은 판정 정확도로 숨은 테스트셋에서의 고침/틀림 수를 추정합니다. |
| `band_guard.py` | 부분집합 가드를 켰을 때의 τ×κ 격자와 2구간 규칙(점수 차 3~4 구간 등)의 효과를 계산합니다. |

평가셋 A~E는 다음과 같습니다.

| 평가셋 | 내용 |
|---|---|
| A | 실제 자매선 쌍 |
| B | 실제 정답 vs 순위 모델 2·3위 |
| C | 합성 한글 근접 동점 |
| D | 합성 자매선 벤치마크 |
| E | 폴드 밖 인코더 기준 가장 헷갈리는 오답 후보 |

## 결론과 리더보드 확인

- 1.7B 모델 결과: 실제 자매선 쌍 정확도 0.985였습니다. 실제 한글 오답 선박 7척은 κ3에서 모두 정답 쪽을 골랐습니다.
- 4B 모델 결과: 정확도는 조금 높았습니다(0.991~0.994). 그러나 Public 결과는 1.7B와 같았습니다.
- 판정 구간: 순위 점수 차 2~3 미만에서만 이득이었습니다. 더 넓히면 κ를 아무리 높여도 실제 리더보드에서 손해였습니다.
- 영문 행 판정: 같은 방식으로 시험했지만 이득이 없어 채택하지 않았습니다.

10-shot 예시 10쌍은 train.csv의 실제 행이라 저장소에 넣지 않았습니다. `judge.py`가 `SEOKCHEON_WS/work/` 아래의 train.csv와 vessel_catalog.csv에서 행 ID로 복원합니다.
